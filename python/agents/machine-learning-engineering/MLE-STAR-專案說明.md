# MLE-STAR 專案說明

本文件旨在詳細說明 MLE-STAR (Machine Learning Engineering Agent via Search and Targeted Refinement) 專案，並回答關於其設計、實作和相關機器學習概念的問題。

## 第一部分：專案總覽

### 1. 專案用途是什麼？
此專案是一個**自動化機器學習工程師 (Automated Machine Learning Engineer)**。

您可以把它想像成一個智慧型機器人，它的目標是**自動解決機器學習問題**。對於一個大學生程度、但沒有機器學習背景的人來說，可以這樣理解：

傳統上，若要解決一個數據預測問題（例如，根據房子的特徵預測房價），需要一位人類專家（機器學習工程師）。這位專家需要：
1. **清理數據**：處理數據中的錯誤或缺失值。
2. **特徵工程**：從原始數據中創造出對預測更有幫助的新特徵。
3. **選擇模型**：從眾多機器學習模型（如 `LightGBM`, `RandomForest`）中挑選合適的。
4. **編寫程式**：用 Python 等語言編寫訓練模型的程式。
5. **反覆實驗**：不斷調整程式和模型參數，以獲得最準確的預測結果。

這個過程非常耗時且需要大量專業知識。

**MLE-STAR 專案的目的就是將上述流程自動化**。使用者只需要提供數據和問題描述（例如，「這是一個房價預測問題，請用這些數據訓練一個模型」），這個專案（代理程式）就會自動上網搜尋最佳實踐、編寫程式碼、進行實驗、除錯、並逐步優化，最終產出一個高品質的機器學習模型和預測結果，其表現甚至能媲美人類專家在 Kaggle 等數據競賽中的水準。

### 2. 專案的 Input/Output 是什麼？
- **Input (輸入):**
    1. **任務描述檔案 (`task_description.txt`)**: 一個純文字檔，用自然語言描述機器學習任務的目標。例如：「這是一個迴歸任務，目標是根據多種人口、地理和財務特徵，預測加州各區域的房價中位數。」
    2. **數據檔案 (例如 `train.csv`, `test.csv`)**: 標準的數據集檔案。`train.csv` 包含帶有正確答案（目標值）的數據，用於訓練機器學習模型；`test.csv` 包含沒有答案的數據，用於生成最終的預測結果。

- **Output (輸出) / 最終產出:**
    1. **完整的 Python 訓練程式 (`final_solution.py`)**: 一個可以直接運行的 Python 腳本。這是整個專案最有價值的產出之一，它包含了從數據讀取、清理、特徵工程到模型訓練和預測的所有邏輯。這份程式碼是經過多輪自動優化後的最終版本。
    2. **預測結果檔案 (`submission.csv`)**: 一個 CSV 檔案，包含了對 `test.csv` 中每一行數據的預測結果。這個檔案的格式通常符合 Kaggle 等競賽平台的要求，可以直接上傳以獲得評分。
    3. **中間過程與日誌 (Workspace)**: 專案在 `workspace` 目錄下會儲存所有中間步驟產生的程式碼、實驗結果、日誌等。這對於理解代理程式的「思考過程」和除錯非常有幫助。

    **作用**: 最終產出的程式碼和預測結果，可以直接應用於實際業務或參加數據科學競賽，解決具體的預測問題。

### 3. 專案用到哪些 LLM？分別用在哪裡？
本專案的核心是透過大型語言模型 (LLM) 來模擬人類工程師的思考和編碼行為。專案在多個環節使用 LLM (可配置，例如 Gemini 系列模型)，每個環節的 LLM 扮演不同角色：

1. **`A_retriever` (模型檢索員)**:
    - **使用位置**: 初始化階段。
    - **LLM 作用**: 接收任務描述後，LLM 會**生成搜尋關鍵字** (例如 "california housing price prediction python code example")，並利用 Google 搜尋工具上網查找相關的機器學習模型和程式碼範例。然後，LLM 會**解析搜尋結果**，提取出最有潛力的模型（如 LightGBM、RandomForest）及其範例程式碼。

2. **程式碼生成與除錯代理程式**:
    - **使用位置**: 初始化、優化和整合階段。
    - **LLM 作用**:
        - **生成完整程式**: 將 `A_retriever` 找到的零散程式碼範例，改編成一個能在此專案數據上運行的完整、獨立的訓練腳本。
        - **修復錯誤 (Debug)**: 當產生的程式碼運行失敗時，系統會捕捉錯誤訊息 (Traceback)，並將**錯誤訊息和原始程式碼**一起發送給 LLM，要求它**修復這個錯誤**。這個過程會循環直到程式碼能成功運行。

3. **`A_abl` (消融研究員)**:
    - **使用位置**: 優化階段 (Refinement)。
    - **LLM 作用**: LLM 接收一份完整的訓練程式碼，並被要求**生成「消融研究」版本的程式碼**。也就是說，LLM 需要策略性地註解掉或移除程式中的某些區塊（例如某個特徵工程步驟），以測試該區塊對最終結果的重要性。

4. **`A_extractor` & `A_planner` (分析師與計劃員)**:
    - **使用位置**: 優化階段。
    - **LLM 作用**:
        - **分析結果**: LLM 負責**解讀消融研究的結果**，找出對模型性能影響最大的「關鍵程式碼區塊」。
        - **制定優化計劃**: 針對這個關鍵區塊，LLM 會**腦力激盪並提出一個改進計劃**。例如：「目前的特徵縮放效果不好，計劃嘗試以下三種策略：1. 改用 `MinMaxScaler`；2. 增加 `RobustScaler`；3. 移除縮放步驟，直接使用原始特徵。」

5. **`A_ensemble` (模型整合專家)**:
    - **使用位置**: 整合階段 (Ensemble)。
    - **LLM 作用**: LLM 接收多個經過優化的不同模型方案，並被要求**設計一個整合策略**，將這些模型的預測結果組合起來，以獲得比任何單一模型都更好的最終預測。例如，LLM 可能會提出「對模型 A 和模型 B 的預測結果進行加權平均，權重分別為 0.7 和 0.3」。接著，它會生成實作這個策略的程式碼。

### 4. Kaggle 的 "california-housing-prices" 與本專案有何相關？
**直接相關**。本專案使用 Kaggle 上的 "california-housing-prices" 數據集作為一個**內建的範例任務**，用來展示和測試整個自動化流程的能力。

- **數據來源**: 專案中的 `tasks/california-housing-prices` 目錄下的 `train.csv` 和 `test.csv` 就是來自這個 Kaggle 任務。
- **任務目標**: 專案解決的問題——預測加州房價——與該 Kaggle 任務的目標完全一致。
- **基準測試**: 透過在這個公開、標準化的任務上運行，開發者可以評估 MLE-STAR 自動產生的模型能達到什麼樣的水平，是否能與人類參賽者一較高下。

簡單來說，"california-housing-prices" 是 MLE-STAR 專案用來「練兵」和「考試」的靶場。
